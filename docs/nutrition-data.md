# 营养数据方案

当前版本已取消“按品类套同一组蛋白/碳水/脂肪”的做法，改为：

- 先按完整菜名匹配常见食物条目。
- 匹配不到完整菜名时，按主要食材组合估算。
- 再按烹饪方式调整油脂和热量。
- 仍匹配不到时才用品类兜底，并把置信度标低。

每个菜品会带 `nutritionMeta`：

- `source`: 数据生成方式。
- `basis`: 使用的菜名或食材关键词。
- `confidence`: 0-1 置信度。
- `reviewed`: 是否人工复核。

## 后续推荐接入的数据源

更可靠的做法是每周上传菜单后做一次“营养生成”任务，而不是用户点菜时临时估算。

优先级建议：

1. 中文商业食物库：唤醒食物、天聚数行食物营养接口，中文菜品覆盖更好。
2. 权威基础库：中国食物成分表，用于基础食材和人工校准。
3. 国际兜底：USDA FoodData Central，适合基础食材，不适合直接匹配中式菜名。
4. AI：只用于拆解菜名、推断做法、选择候选食材，不作为唯一营养来源。

## 每周更新流程

1. 菜单图片放入 `menu-images/`。
2. OCR 或人工整理出菜名。
3. 调用云函数 `analyzeMenuNutrition` 批量生成每 100g 数据。
4. 对 `confidence < 0.55` 的菜人工复核。
5. 把复核后的结果写回云端菜单，前端只展示最终结果。
